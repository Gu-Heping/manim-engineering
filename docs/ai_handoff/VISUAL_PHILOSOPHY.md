# VISUAL_PHILOSOPHY (for AI engineers)

## Core thesis

Visuals are a projection of engineering state transitions, not slide decoration.

## “Physical-meaning driven” in practice

- A pulse exists because a semantic propagation record exists.
- A waveform segment appears because reveal time/beat advances.
- A color exists because signal type maps to renderer theme.
- A pause exists because reading/comprehension needs temporal spacing.

If motion cannot be explained by a semantic event, remove it.

## What “not PPT animation” means here

- No arbitrary entrance effects for unrelated groups.
- No synchronized “everything fades in” choreography.
- No cosmetic rhythm that hides causal order.
- No dramatic camera behavior that competes with the concept.

## 3B1B style adaptation (bounded, not copied)

- Dark but readable background.
- Progressive reveal over dense static dumps.
- Focus hierarchy: active path > active component > context.
- Motion minimalism: one concept per moment is preferred.

## Readability hierarchy

1. Topology legibility.
2. Causal flow legibility.
3. Timing legibility.
4. Aesthetic consistency.

Never invert this order.

## Visual compromises that are intentional

- Educational time scaling may exaggerate duration.
- Symbol geometry may be simplified for clarity.
- Idle stubs and hold extensions are teaching devices, not physics simulation.

## Anti-pattern checklist

- Does this change add motion without new semantic information?
- Does it increase simultaneous attention targets?
- Does it make deterministic tests harder to keep stable?
- Does it bypass scene template contracts?

If any answer is yes, redesign before merging.
